## わかったこと
- Go 言語
  - Go の interface
    - 呼び出し元が必要とするメソッドだけを定めた契約（満たせば、どんな実装でも受け入れる）
  - エクスポート（識別子の大文字・小文字）
    - 大文字始まり：他のパッケージから利用できる（エクスポートされる）
    - 小文字始まり：同じパッケージ内でのみ利用できる
    - 関数・型・構造体のフィールド・メソッド・定数・変数など、パッケージレベルの識別子に適用される

- リポジトリインターフェース（ドメイン層）
  - リポジトリに必要な振る舞い（保存・取得など）を、メソッド名・引数・戻り値だけで定義する（処理の中身は持たない）
- リポジトリ実装（インフラ層）
  - ドメイン層のリポジトリインターフェースを満たすように、DB への保存・取得処理（永続化）を実装する
  - DB 用のモデルとドメインのエンティティを相互に変換する（adapt）

## 感じたこと
- Go  の Interface を API（Application Programming Interface）のような「処理を持つ入口」だと思い込み、実際のコードで「何が定義され、何が実行されるか」を確かめていなかったため、理解に時間がかかった
  - 実際は、interface はメソッドの形を定義するだけで、実行されるのは interface 型の変数に代入された構造体のメソッドだった
- 今後は、用語の名前から意味を推測せず、「何が定義され、何が実行されるか」をコードで確認するようにしたい

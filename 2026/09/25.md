  ## わかったこと
  ### Go の格言（Go Proverbs）
    - Go においての戒めや教訓を短くまとめたもの
    - 同じ呼び名の[囲碁の格言](https://ja.wikipedia.org/wiki/囲碁の格言)を真似て作られた
      - ※ 囲碁は英語で Go、囲碁の格言は Go Proverbs という
    - Go の生みの親の一人である、Rob Pike が 2015 年の Gopherfest のセッションで発表した
      - ※「Don't panic.」のみセッションでは発表されておらず Code Review Comments から参照している
    - URL
      - https://www.youtube.com/watch?v=PAAkCSZUG1c
      - https://go-proverbs.github.io/
      - https://go.dev/wiki/CodeReviewComments#dont-panic

  ### 格言一覧
  1. Don't communicate by sharing memory, share memory by communicating.  
    メモリを共有することで通信するな。通信することでメモリを共有せよ。

  2. Concurrency is not parallelism.  
    並行性は並列性ではない。

  3. Channels orchestrate; mutexes serialize.  
    チャネルは編成し、ミューテックスは直列化する。

  4. The bigger the interface, the weaker the abstraction.  
    インタフェースが大きければ大きいほど、抽象化は弱くなる。

  5. Make the zero value useful.  
    ゼロ値を有用にせよ。

  6. interface{} says nothing.  
    interface{} は何も語らない。

  7. Gofmt's style is no one's favorite, yet gofmt is everyone's favorite.  
    gofmt のスタイルは誰のお気に入りでもない。それでも gofmt は皆のお気に入りだ。

  8. A little copying is better than a little dependency.  
    少しのコピーは、少しの依存よりも良い。

  9. Syscall must always be guarded with build tags.  
    syscall は常にビルドタグで保護されなければならない。

  10. Cgo must always be guarded with build tags.  
      cgo は常にビルドタグで保護されなければならない。

  11. Cgo is not Go.  
      cgo は Go ではない。

  12. With the unsafe package there are no guarantees.  
      unsafe パッケージでは、何も保証されない。

  13. Clear is better than clever.  
      明快さは、巧妙さよりも良い。

  14. Reflection is never clear.  
      リフレクションは決して明快ではない。

  15. Errors are values.  
      エラーとは値である。

  16. Don't just check errors, handle them gracefully.  
      エラーをただチェックするのではなく、上手に処理せよ。

  17. Design the architecture, name the components, document the details.  
      アーキテクチャを設計し、コンポーネントに名前を付け、詳細を文書化せよ。

  18. Documentation is for users.  
      ドキュメントはユーザーのためのものである。

  19. Don't panic.  
      panic するな。（通常のエラー処理に panic を使うな。error と多値返却を使え。）

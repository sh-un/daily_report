- テーブル駆動テストとは
  - テストケース（入力と期待する結果）を「テーブル（表）」にまとめ、ループで1件ずつ、実際の結果が期待する結果と一致するかを確認する書き方。
  - Go 公式 Wiki でもテーブル駆動テストの書き方が紹介されている。
  - Go の標準ライブラリ（`fmt` など）のテストでも使われている。
  - メリット
    - テーブルに1行追加するだけで、テストケースを増やせる。
    - 同じテスト処理をケースごとに書く必要がない。
    - 入力と期待する結果がまとまっているため、テスト内容を確認しやすい。

  - [例）文字列を逆順にする関数のテスト](https://go.dev/doc/code#Testing)

    ```go
    func TestReverseRunes(t *testing.T) {
        // テーブル：1行が1つのテストケース
        cases := []struct {
            // 列の定義
            in   string // 入力（逆順にしたい文字列）
            want string // 期待する結果（逆順になった文字列）
        }{
            // 行（ここに1行足すとケースが増える）
            {"Hello, world", "dlrow ,olleH"}, // ケース1：英語の文字列
            {"Hello, 世界", "界世 ,olleH"},    // ケース2：日本語を含む文字列
            {"", ""},                         // ケース3：空文字
        }

        // テーブルから1件ずつ取り出し、実際の結果と期待する結果を比較する
        for _, c := range cases {
            got := ReverseRunes(c.in) // 実際の結果
            if got != c.want {        // 実際の結果と期待する結果が違えば失敗
                // 入力・実際の結果・期待する結果を表示する
                t.Errorf("ReverseRunes(%q) == %q, want %q", c.in, got, c.want)
            }
        }
    }
    ```

- テストの実行
  - `go test` コマンドで実行し、結果はターミナルに表示される。
  - 成功時は `ok` などの簡単な結果が表示され、失敗時は失敗したテストとエラーメッセージが表示される。
  - `-v` を付けると、成功したテストやサブテストを含め、実行結果を詳しく確認できる。

- テストで使う主なメソッド（`*testing.T` のメソッド）
  - `t.Run`
    - テストケースごとに名前を付けて実行する。
    - 例）`TestXxx` の中で `t.Run("success", ...)` と書くと、`-v` 付きで実行したときに `--- PASS: TestXxx/success` と表示される。`/` の前がテスト関数名、後ろが `t.Run` で付けたサブテスト名になる。
  - `t.Cleanup`
    - テスト終了時に実行する後片付けを登録する。
    - 例）DB のロールバックを登録しておくと、テスト終了時に DB をテスト前の状態に戻せる。

  - `t.Error` / `t.Errorf`
    - テストを失敗扱いにする。処理はそのまま続く。
    - 例）期待値と実際の値が違う場合に `t.Errorf("got %v, want %v", got, want)` と書くと、値の違いを表示してテストを失敗扱いにできる。

  - `t.Fatal` / `t.Fatalf`
    - テストを失敗扱いにし、その場で処理を止める。
    - 例）DB への保存処理がエラーになった場合、その後の「保存された内容が正しいか」という確認はできないため、その時点でテストを止める。

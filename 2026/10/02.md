## わかったこと
- 参考URL
  - https://gorm.io/docs/models.html
    - Pointers to types like `*string` and `*time.Time` indicate nullable fields.
    - `*string` や `*time.Time` のようなポインタ型は、NULL を許容するフィールドであることを示す。
    - `sql.NullString` and `sql.NullTime` from the `database/sql` package are used for nullable fields with more control.
    - `database/sql` パッケージの `sql.NullString` と `sql.NullTime` は、より詳細な制御が可能な NULL 許容フィールドで使用されます。
  - https://pkg.go.dev/database/sql#NullString

- GORM モデルの NULL 許容フィールドの書き方（2通り）
  1. ポインタ型（`*string`、`*time.Time` など）
    - `nil` を NULL として扱う
  2. `database/sql` の型（`sql.NullString`、`sql.NullTime` など）
    - 値と、NULL かどうかを表す bool 値（`Valid`）を持つ構造体
    - `Valid` が `true` なら値あり、`false` なら NULL
      - 例）Go 標準ライブラリの `sql.NullString` の定義
        ```go
        type NullString struct {
          String string // 値
          Valid  bool   // true なら値あり、false なら NULL
        }
        ```

      - 例）GORM 公式ドキュメントの例
        ```go
        type User struct {
          ID           uint
          Name         string
          Email        *string        // NULL を許容。文字列へのポインタ
          Age          uint8
          Birthday     *time.Time     // NULL を許容。time.Time へのポインタ
          MemberNumber sql.NullString // NULL を許容。NULL かどうかの bool 値をフィールドに持つ構造体
          ActivatedAt  sql.NullTime   // NULL を許容。NULL かどうかの bool 値をフィールドに持つ構造体
          CreatedAt    time.Time
          UpdatedAt    time.Time
          ignored      string
        }
        ```

- GORM モデルで NULL を扱うフィールドに、ポインタ型や `sql.Null` 型が必要な理由
  - 通常の型（`string` など）は、必ずゼロ値（空文字など）を持つ
  - そのため、空文字と NULL を区別できない
  - ポインタ型や `sql.Null` 型を使うと、NULL を表せる

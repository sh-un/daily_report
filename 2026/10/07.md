## わかったこと
- ダックタイピング（振る舞いに基づく型付け）
  - 以下のことわざに由来し、振る舞いによる判断をプログラミングの型付けに応用した考え方。
    - 「アヒルのように歩き、アヒルのように鳴くなら、それはアヒルだ」
    - 「歩く」「鳴く」といった振る舞い（メソッド）を持つかどうかで、「アヒル」として扱えるかを判断する

- Go のインターフェースの暗黙的な実装への当てはめ
  - 型（具体）のメソッド（振る舞い）に、インターフェース型（抽象）が定義するメソッドがすべて含まれていれば、そのインターフェース型（抽象）として扱える点で、ダックタイピングと同じ考え方だと理解できる。

- コード例
  ```go
  // 抽象：動物の鳴き声を定義
  type Animal interface {
      Sound() string
  }

  // 具体：アヒル
  type Duck struct{}

  // Animal に定義されたメソッドを実装
  func (Duck) Sound() string {
      return "アフラック！"
  }

  // Duck は Animal を暗黙的に実装
  var animal Animal = Duck{}
  ```

## 感じたこと
- Go のインターフェースの暗黙的な実装には、以下のようなメリットがあるとされているが、まだ理解が浅いため、今後の実装を通して理解を深めたい。
  - 関心の分離（Separation of Concerns：SoC）
    - 型とインターフェースを独立して定義でき、型の実装時にインターフェースを意識する必要がない。
  - コードの再利用性・拡張性（Code Reuse / Extensibility）
    - 既存の型を変更せずに、後からインターフェースを定義して利用できる。
    - 開発中に新しい用途や必要な振る舞いが見つかった場合も、それに合わせてインターフェースを追加できる。

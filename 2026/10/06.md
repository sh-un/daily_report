- インターフェースの暗黙的な実装の検証
  - 型がインターフェースのメソッドを実装し忘れていても、その型をインターフェースとして使う箇所がなければコンパイルエラーにならないため、実装を検証する方法があることを知った。

- 検証方法の例
  - `var _ Animal = Dog{}` のように、インターフェース型の変数に型の値を代入する。
  - `_`（ブランク識別子）に代入するため、値は使われずに捨てられる。
  - `Dog` が `Animal` を実装していなければ代入できず、コンパイルエラーになる。
  - 実装関係をコード上に明示でき、実装漏れにも早い段階で気づける。
    ```go
    type Animal interface {
        Sound() string
    }

    type Dog struct {
        Name string
    }

    func (d Dog) Sound() string {
        return "ヨン！"
    }

    // コンパイル時に Dog が Animal を実装しているか検証
    var _ Animal = Dog{}

    var animal Animal = Dog{Name: "４と鳴く犬"}
    ```

- ポインタレシーバーの場合
  - レシーバーがポインタ（`*Dog`）のメソッドは `Dog` のメソッドセットに含まれないため、`*Dog` で検証する。
    ```go
    func (d *Dog) Sound() string {
        return "ヨン！"
    }

    var _ Animal = Dog{}       // コンパイルエラー
    var _ Animal = (*Dog)(nil) // OK
    ```

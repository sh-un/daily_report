## わかったこと
- Input Port
  - クリーンアーキテクチャの用語
  - ユースケース層の入り口。ハンドラ層は、この入り口を通してユースケースを呼び出す。
  - Go では interface で実現する（例：`type UserUsecase interface`）
- Interactor
  - クリーンアーキテクチャの用語
  - Input Port を実装し、ユースケースを実行するもの。リポジトリなどを組み合わせて処理を行う。
  - Go では struct で実現する（例：`type UserUsecaseImpl struct`）

- interface と struct に分ける理由
  - interface と struct は同じ名前にできないため、struct 側に `Impl` を付けている。
  - インフラ層のリポジトリと同じ構造。ハンドラ層は interface（Input Port）だけに依存することで、struct（Interactor）をモックに差し替えられる。これにより、ハンドラ層だけを単独でテストできる。
  - 依存関係（interface と struct の対応）
      | 呼び出し元 | interface | struct |
      | --- | --- | --- |
      | ユースケース層 | `UserRepository`（ドメイン層） | `userRepository`（インフラ層） |
      | ハンドラ層 | `UserUsecase`（ユースケース層） | `UserUsecaseImpl`（ユースケース層） |

  - コード例（ユースケース層）
    ```go
    type UserCreateInput struct {
      Name string
    }

    // Input Port（interface）
    type UserUsecase interface {
      Create(ctx context.Context, input *UserCreateInput) (*domain.User, error)
    }

    // Interactor（struct）
    type UserUsecaseImpl struct {
      userRepos domain.UserRepository
    }

    func NewUserUsecase(userRepos domain.UserRepository) UserUsecase {
      return &UserUsecaseImpl{userRepos: userRepos}
    }

    func (u *UserUsecaseImpl) Create(ctx context.Context, input *UserCreateInput) (*domain.User, error) {
      user := &domain.User{Name: input.Name}
      if err := u.userRepos.Save(ctx, user); err != nil {
        return nil, err
      }
      return user, nil
    }
    ```
